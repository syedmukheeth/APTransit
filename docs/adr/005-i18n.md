# ADR 005 · next-intl, English and Telugu, cookie based locale

**Status:** Accepted, Day 0.

## Context

Plan sec 48: launch in English and Telugu, all translations in one place, not in code.

## Decision

- next-intl with messages in `apps/web/messages/en.json` and `te.json`.
- Locale from a `locale` cookie (default from `Accept-Language`, then `en`), no URL prefix. The PWA feels like an app, so clean URLs matter more than locale specific SEO.
- `<html lang>` follows the locale. Telugu uses Noto Sans Telugu and a taller line height.
- Server stores `users.preferredLocale` so emails and notifications use the right language.
- CI check: both files have identical key sets, no empty values, no em or en dash.

## Consequences

- Adding a language later means one new JSON file and one font.
- Public pages are not indexed per language. Acceptable for this product.
